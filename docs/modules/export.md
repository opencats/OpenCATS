# Module: export

## Overview

The export module is the CSV/data-export controller. Its controller class is declared as:

```php
class ExportUI extends UserInterface
```

(modules/export/ExportUI.php:41)

The file header is leftover boilerplate that mislabels it as the "RSS Feed module" / a "BASIC guide to the CATS module API" (modules/export/ExportUI.php:4, :27-31); the actual code is the data-export controller.

Constructor (modules/export/ExportUI.php:43-52):

```php
public function __construct()
{
    parent::__construct();

    $this->_authenticationRequired = true;
    $this->_moduleDirectory = 'export';
    $this->_moduleName = 'export';
    $this->_moduleTabText = '';
    $this->_subTabs = array();
}
```

Key facts derived from the source:

- It requires authentication only (`$this->_authenticationRequired = true`, modules/export/ExportUI.php:47). There is **no** per-action access-level guard — the module never calls `getUserAccessLevel(...)` anywhere (verified by grep over `modules/export/` and `lib/Export.php`: no matches). Any authenticated user can reach both actions.
- `$this->_moduleTabText = ''` (modules/export/ExportUI.php:50) — the module renders no top navigation tab; it is invoked only via direct `m=export` URLs / forms built elsewhere.
- Two top-level includes pull in the export engine and error helper (modules/export/ExportUI.php:37-38):
  - `include_once(LEGACY_ROOT . '/lib/Export.php');`
  - `include_once(LEGACY_ROOT . '/lib/CommonErrors.php');`

What it exports and in what format:

- **Output format is CSV.** Both code paths emit a downloadable file named `export.csv`.
- The `export`/default action produces output via `Export::getFormattedOutput()`, which only supports candidate data (`DATA_ITEM_CANDIDATE`); all other data-item types fall through to `return false` (lib/Export.php:132-141). Fields are double-quote-escaped and joined with a comma separator passed in by the controller (lib/Export.php:117, lib/Export.php:150-169). Records are terminated with `\r\n`.
- The `exportByDataGrid` action delegates to `DataGrid::drawCSV()` (lib/DataGrid.php:1444), which streams a CSV built from whatever columns the grid declares exportable.

## Per-action detail with cites

### `export` / default — `onExport()` (modules/export/ExportUI.php:77-127)

1. Hardcodes the download filename: `$filename = 'export.csv';` (modules/export/ExportUI.php:79).
2. Validates the data-item type: `if (!$this->isRequiredIDValid('dataItemType', $_GET))` → on failure `CommonErrors::fatal(COMMONERROR_BADFIELDS, $this, 'Invalid data item type.')` (modules/export/ExportUI.php:82-85). `isRequiredIDValid` requires the key to be present, non-empty, and all digits (lib/UserInterface.php:318-328).
3. Reads `$dataItemType = $_GET['dataItemType'];` (modules/export/ExportUI.php:87).
4. Selection-mode resolution:
   - **Only-Selected mode** — if `$this->isChecked('onlySelected', $_GET)` (modules/export/ExportUI.php:90; helper lib/UserInterface.php:356-365), it scans every `$_GET` key, keeps those containing `checked_`, and strips the `checked_` prefix to build `$IDs[]` (modules/export/ExportUI.php:92-100). These `checked_<id>` params come from the export form/checkboxes generated by `ExportUtility::getForm()` (lib/Export.php:53-98).
   - **Page mode** — otherwise, `$tempIDs = $this->getTrimmedInput('ids', $_GET)` (modules/export/ExportUI.php:105; helper lib/UserInterface.php:374-382); if non-empty, `$IDs = explode(',', $tempIDs)` (modules/export/ExportUI.php:108).
   - **All-Records mode** — otherwise `$IDs = array();` (modules/export/ExportUI.php:113).
5. Builds the engine and renders: `$export = new Export($dataItemType, $IDs, ',', $this->_siteID);` then `$output = $export->getFormattedOutput();` (modules/export/ExportUI.php:117-118). Note the separator passed in is a literal comma.
6. Fires the EXPORT hook as a gate: `if (!eval(Hooks::get('EXPORT'))) return;` (modules/export/ExportUI.php:120). If the hook evaluates falsy, the download is suppressed.
7. Emits download headers and echoes the body (modules/export/ExportUI.php:122-126):

```php
header('Content-Disposition: attachment; filename="' . $filename . '"');
header('Content-Length: ' . strlen($output));
header('Connection: close');
header('Content-Type: text/x-csv; name=' . $filename);
echo $output;
```

Note: there is no explicit handling of `getFormattedOutput()` returning `false` (e.g. for a non-candidate `dataItemType`, lib/Export.php:138-139, or empty result set, lib/Export.php:144-147). In that case `$output === false`, `strlen($output)` is `0`, and an empty/zero-length CSV is sent.

### `exportByDataGrid` — `onExportByDataGrid()` (modules/export/ExportUI.php:135-140)

```php
public function onExportByDataGrid()
{
    $dataGrid = DataGrid::getFromRequest();

    $dataGrid->drawCSV();
}
```

- `DataGrid::getFromRequest()` rebuilds the grid from the request: it requires `$_REQUEST['i']` (the datagrid identifier) and optionally decodes `$_REQUEST['p']` JSON parameters; returns `null` if `i` is missing (lib/DataGrid.php:315-337). If `null`, the subsequent `$dataGrid->drawCSV()` call would fatal on a non-object.
- `drawCSV()` (lib/DataGrid.php:1444-1554) loads grid data via `_getData()`, then determines exportable columns: a column is excluded when its name is empty, when `exportable === false`, or when it has neither a `sortableColumn` nor an `exportRender` (lib/DataGrid.php:1463-1474). Header text comes from `exportColumnHeaderText` if set, else the column name, with `"` escaped to `""` (lib/DataGrid.php:1477-1485).
- Each cell value is produced either by `eval($data['data']['exportRender'])` or by reading `$rsData[$sortableColumn]` (lib/DataGrid.php:1502-1509), then double-quote-escaped and wrapped in quotes (lib/DataGrid.php:1511-1514). Rows joined with `,` and `\r\n` (lib/DataGrid.php:1517-1519).
- Output headers and an optional UTF BOM prefix are written, then header row and rows are echoed, ending in `die()` (lib/DataGrid.php:1523-1553). The download filename is the hardcoded `export.csv` (lib/DataGrid.php:1523). Optional BOM bytes are emitted when `INSERT_BOM_CSV_LENGTH > 0` (lib/DataGrid.php:1528-1543).
- This action does **not** fire the EXPORT hook (no `Hooks::get('EXPORT')` in this path).

### `fatal()` override (modules/export/ExportUI.php:149-152)

The module overrides the base fatal handler to a bare-bones text die (no template):

```php
protected function fatal($error, $directoryOverride = '')
{
    die("Fatal Error\n\n" . $error);
}
```

### DataGrid selection / DATA_ITEM_* ties

- The `export` action keys entirely off the numeric `dataItemType` request value, which maps to the `DATA_ITEM_*` constants in constants.php:57-65: `DATA_ITEM_CANDIDATE = 100`, `DATA_ITEM_COMPANY = 200`, `DATA_ITEM_CONTACT = 300`, `DATA_ITEM_JOBORDER = 400`, etc. Despite the constant set, `Export::getFormattedOutput()` only supports `DATA_ITEM_CANDIDATE` (lib/Export.php:134) — every other type returns `false` (lib/Export.php:138-139).
- Selection of which records to export is driven by request data: `checked_<id>` checkbox params (Only-Selected), the comma-joined `ids` param (Page), or none (All Records) — produced by `ExportUtility::getForm()` (lib/Export.php:58-89) and parsed in `onExport()` (modules/export/ExportUI.php:90-115).
- The `exportByDataGrid` action does not use `DATA_ITEM_*` at all; it reconstructs a `DataGrid` from `$_REQUEST['i']`/`$_REQUEST['p']` (lib/DataGrid.php:315-337) and exports the grid's own declared columns.

## Hooks fired (EXPORT key + cites)

- The `EXPORT` hook is fired once, in `onExport()`: `if (!eval(Hooks::get('EXPORT'))) return;` (modules/export/ExportUI.php:120).
- `Hooks::get($hookName)` (lib/Hooks.php:52) returns concatenated hook command strings from `$_SESSION['hooks']['EXPORT']` plus a trailing `return true;`; if no session hooks are registered it returns `'return true;'` (lib/Hooks.php:54-72). So by default the gate evaluates true and export proceeds.
- The `exportByDataGrid` action fires **no** hook (verified: no `Hooks::get` call in `onExportByDataGrid()` or `drawCSV()`).
- No `EXPORT` hook is registered anywhere in this repo's lib/Hooks.php (the class only defines `get()`); registration would come from external modules populating `$_SESSION['hooks']`.

## Unverified / open questions

- **No access-level guard.** Neither action calls `getUserAccessLevel(...)`; access is gated only by `_authenticationRequired = true`. Whether the framework's front controller (index dispatcher) imposes any additional ACL before reaching `ExportUI` was not traced here.
- **`getFromRequest()` returning `null`.** `onExportByDataGrid()` does not null-check the result before `$dataGrid->drawCSV()`; behavior when `$_REQUEST['i']` is missing (PHP error vs. handled) was not exercised.
- **Empty/false output in `onExport()`.** When `getFormattedOutput()` returns `false` (non-candidate type or empty result set), the controller still sends download headers with `Content-Length: 0`; this was inferred from code, not run.
